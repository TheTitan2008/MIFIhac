## Новая бизнес-проблема

Обычный LLM-веб-чат имеет около 1300 пользователей в месяц. Агентская
платформа — около 150, но расходует примерно в пять раз больше токенов.
Руководство хочет понять, создают ли эти расходы измеримую экономию денег,
рабочего времени и FTE.

Для обычного чата уже применяется экспертная методика:

```text
количество запросов
× экспертная экономия минут по категории
× коэффициент сессии 0.3 / 1 / 2
```

Для агентского продукта эта методика может давать двойной подсчёт, потому что
одна пользовательская цель порождает много внутренних LLM-вызовов.

## Задача

Обнови стратегию так, чтобы единицей анализа стал законченный `agent run`, а не
внутренний запрос или токен. Добавь:

1. модель gross value, agent cost, net value и ROI;
2. расчёт net saved time с учётом review и rework;
3. различие между экспертным baseline и измеренным causal effect;
4. confidence interval или sensitivity analysis assumptions;
5. способ сравнения веб-чата и агентской платформы по завершённым задачам;
6. метрики успешности agent run;
7. поля данных и synthetic generator для tool calls, ошибок, стоимости,
   ручной проверки и baseline;
8. экран dashboard «ценность против стоимости»;
9. объяснение, когда высокий расход токенов оправдан;
10. экспериментальный план дальнейшей валидации: time study, paired tasks или
    сравнение с контрольной группой.

## Ограничения

- Не выдавай экспертные минуты за доказанную экономию.
- Не считай внутренние LLM-вызовы отдельными бизнес-задачами.
- Не делай токены прямой метрикой пользы.
- Не заявляй денежный ROI без отображения assumptions.
- Не расширяй MVP несвязанными функциями.
- Сохрани обязательную классификацию и обнаружение use cases из исходного
  кейса: экономическая модель должна строиться поверх них.
