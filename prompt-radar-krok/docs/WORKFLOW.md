# Экономный процесс работы

## GitHub

- Репозиторий: `https://github.com/TheTitan2008/MIFIhac`
- Основная ветка: `main`.
- Реализацию вести в ветках с префиксом `codex/`.
- Только implementation lead интегрирует изменения в общую ветку.
- Стратегические чаты записывают документы последовательно, а не параллельно.
- Не разрешать двум агентам одновременно менять один файл.

## Схема чатов

```text
Стратег
  ↓ один выбранный вариант
Red-team критик
  ↓ исправленное техническое задание
Implementation lead
  ├─ субагент Data/ML
  ├─ субагент API/pipeline
  └─ субагент Dashboard
  ↓ работающий end-to-end прототип
QA/release
  ↓ подтверждённые метрики и запуск
Pitch/demo
```

## Какие модели куда направлять

- Самая сильная модель: стратегия, red-team и финальный питч.
- Сильная кодовая модель: implementation lead.
- Более дешёвые кодовые агенты: ограниченные реализации модулей с тестами.
- Review-модель: проверка кода, воспроизводимости и безопасности.

Не использовать слабую модель для изменения архитектуры. Она реализует только
утверждённую спецификацию.

## Правила экономии лимитов

1. Стратег создаёт максимум три варианта и выбирает один.
2. Red-team проводится один раз перед кодированием.
3. После утверждения архитектуры запрещён повторный brainstorming без
   обнаруженного блокера.
4. Один владелец интеграции принимает изменения субагентов.
5. Каждый субагент получает конкретные файлы, интерфейс и критерий готовности.
6. Не создавать отдельный чат для задачи короче примерно 30 минут.
7. Не делать презентацию до прохождения smoke test.
8. Все выводы сохранять в файлах, а не держать только в истории чата.

## Gates

### Gate 1 — концепция

- выбрана одна архитектура;
- определена одна главная вау-фича;
- сформулирован demo flow;
- зафиксированы метрики качества.

### Gate 2 — данные

- генератор воспроизводим;
- есть train/validation/test без утечки шаблонов;
- синтетические данные явно помечены;
- есть ручной gold subset.

### Gate 3 — end-to-end

- один запуск обрабатывает данные;
- формируются категории и сценарии;
- дашборд читает результаты;
- есть понятная CTO-рекомендация.

### Gate 4 — релиз

- чистая установка;
- тесты;
- измерены скорость и качество;
- подготовлен fallback без внешнего API;
- записан сценарий демонстрации.
